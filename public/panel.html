Outbound routing

Controls how this Worker reaches the destinations your clients ask for. This is server-side relay behaviour, not a client setting — it does not appear in share links or config files.

Off dials the destination directly. Proxy IP tries one or more intermediate addresses first. NAT64 rewrites IPv4 destinations into IPv6 form — experimental, see the note below.
One IPv4 address or hostname per line. Private, loopback, and documentation ranges are refused. The first one that connects wins; the rest are tried in order.
How many candidates to try before giving up (1–8).
One /96 prefix per line. The first valid one is used; 64:ff9b::/96 is the default if none apply.

Experimental — measured not to work on workers.dev as of 2026-08. Two runtime limits stack up: the destination must already be an IPv4 literal (a domain cannot be synthesised, because the runtime exposes no DNS API, so domains fall back to direct), and outbound dials to IPv6 literals were observed to fail regardless of NAT64 — a native IPv6 address that answers from elsewhere does not connect from a Worker. Since NAT64 can only ever produce an IPv6 target, it has nothing to succeed with. Left in place because it costs nothing when unused and the runtime may gain IPv6 egress later. Use Proxy IP instead; that path is verified working.
